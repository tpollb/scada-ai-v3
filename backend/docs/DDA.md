## Введение

Модуль **Deep Data Analysis (DDA)** предназначен для комплексного анализа временных рядов данных SCADA-систем. Модуль предоставляет:

- **Детекцию аномалий** с использованием алгоритма Isolation Forest
- **Классификацию аномалий** по типам: пики (spike), провалы (dip), дрейфы (drift), шум (noise)
- **Корреляционный анализ** между несколькими тегами
- **Визуализацию** с интерактивными графиками и тепловой картой корреляций
- **Конфигурируемость** через UI-интерфейс настроек

### Ключевые возможности

- [x] Анализ одиночных тегов и множественных тегов
- [x] Автоматическая классификация типов аномалий
- [x] Интерактивные графики с zoom/pan
- [x] Настраиваемые пороги детекции
- [x] Корреляционный анализ с визуализацией
- [x] Экспорт результатов в PNG

## Математические основы

### 1. Isolation Forest

**Isolation Forest** — алгоритм машинного обучения для детекции аномалий, основанный на принципе "изоляции".

#### Основная идея

Аномальные точки легче "изолировать" (отделить от остальных) чем нормальные точки. Алгоритм строит набор случайных деревьев решений (isolation trees) и измеряет среднюю глубину изоляции каждой точки.

#### Алгоритм построения Isolation Tree

Для каждого дерева:

1. **Инициализация:** выбираем подвыборку размера `ψ` (обычно 256 точек)
2. **Рекурсивное разделение:**
   - Выбираем случайный признак (в нашем случае — индекс точки)
   - Выбираем случайное значение разделения `split_value` между min и max
   - Разделяем данные на две части: `x < split_value` и `x >= split_value`
3. **Остановка:** когда достигнута максимальная глубина или все точки разделены

#### Математическая формула

**Anomaly Score** для точки `x`:

```
s(x, n) = 2^(-E(h(x)) / c(n))
```

Где:
- `E(h(x))` — средняя глубина изоляции точки `x` по всем деревьям
- `c(n)` — нормализующий фактор (средняя глубина в бинарном дереве поиска)

**Нормализующий фактор:**

```
c(n) = 2H(n-1) - 2(n-1)/n

H(i) ≈ ln(i) + 0.5772156649 (гармоническое число)
```

#### Интерпретация результатов

- `s(x, n) → 1`: точка является аномалией (легко изолируется)
- `s(x, n) → 0.5`: точка нормальная
- `s(x, n) → 0`: точка является аномалией (но в другом смысле)

#### Параметры алгоритма

- **contamination** (загрязнение): доля аномалий в данных (0.01 - 0.5)
- **n_estimators**: количество деревьев (обычно 100)
- **max_samples**: размер подвыборки для каждого дерева

### 2. Классификация аномалий

После детекции аномалий алгоритм классифицирует их по типам на основе локального контекста.

#### Методология

Для каждой аномальной точки анализируется окно `W` (обычно ±5 точек):

```
W = [x(t-w), ..., x(t-1), x(t), x(t+1), ..., x(t+w)]
```

#### Типы аномалий

##### Spike (Пик)

**Определение:** резкое отклонение вверх от локального тренда

**Критерии:**
```
spike = (x(t) > mean(W \ {x(t)}) + 2σ) AND 
        (|x(t) - x(t-1)| > threshold) AND
        (|x(t) - x(t+1)| > threshold)
```

**Физический смысл:** кратковременный всплеск значения (например, помеха датчика)

##### Dip (Провал)

**Определение:** резкое отклонение вниз от локального тренда

**Критерии:**
```
dip = (x(t) < mean(W \ {x(t)}) - 2σ) AND 
      (|x(t) - x(t-1)| > threshold) AND
      (|x(t) - x(t+1)| > threshold)
```

**Физический смысл:** кратковременное падение значения (например, обрыв сигнала)

##### Drift (Дрейф)

**Определение:** постепенное отклонение от базового уровня

**Критерии:**
```
drift = |x(t) - baseline(t)| > threshold

baseline(t) = moving_average(W) или экспоненциальное сглаживание
```

**Физический смысл:** медленное изменение значения (например, износ оборудования)

##### Noise (Шум)

**Определение:** аномалия, не попадающая под другие категории

**Критерии:**
```
noise = is_anomaly(x(t)) AND 
        NOT (spike OR dip OR drift)
```

**Физический смысл:** случайные флуктуации или неклассифицируемые аномалии

### 3. Корреляционный анализ

#### Коэффициент корреляции Пирсона

**Формула:**

```
r(X, Y) = Σ((xᵢ - x̄)(yᵢ - ȳ)) / √(Σ(xᵢ - x̄)² · Σ(yᵢ - ȳ)²)
```

Где:
- `X, Y` — два временных ряда
- `x̄, ȳ` — средние значения
- `r ∈ [-1, 1]`

#### Интерпретация

- `r = 1`: полная положительная корреляция
- `r = -1`: полная отрицательная корреляция
- `r = 0`: отсутствие линейной корреляции

#### Матрица корреляций

Для `n` тегов строится матрица `C` размером `n × n`:

```
C[i, j] = r(tagᵢ, tagⱼ)
```

**Свойства:**
- Симметричность: `C[i, j] = C[j, i]`
- Диагональ: `C[i, i] = 1` (корреляция с самим собой)

### 4. Downsampling (понижение частоты дискретизации)

#### Min-Max Downsampling

Для визуализации больших объёмов данных применяется min-max downsampling.

**Алгоритм:**

1. Разделяем данные на `N` bucket'ов (корзин)
2. Для каждого bucket находим:
   - `min_value` с его индексом `i_min`
   - `max_value` с его индексом `i_max`
3. Добавляем обе точки в хронологическом порядке

**Преимущества:**
- Сохраняет экстремумы (пики и провалы)
- Уменьшает количество точек в 2-3 раза
- Быстрый алгоритм O(n)

**Формула размера bucket:**

```
bucket_size = total_points / target_points
```

## Конфигуратор параметров

### Доступ к конфигуратору

Конфигуратор открывается через кнопку ⚙️ (настройки) в панели Deep Data Analysis.

### Вкладки конфигуратора

#### 1. Детекция аномалий

##### Contamination (Загрязнение)

**Описание:** Ожидаемая доля аномалий в данных

**Диапазон:** 0.01 - 0.5  
**По умолчанию:** 0.08 (8%)

**Рекомендации:**
- `0.01-0.05`: для чистых данных с редкими аномалиями
- `0.05-0.10`: для типичных производственных данных
- `0.10-0.20`: для зашумлённых данных
- `0.20-0.50`: для данных с большим количеством аномалий

**Влияние:**
- Увеличение → больше точек помечается как аномалии
- Уменьшение → более строгая фильтрация

##### N Estimators (Количество деревьев)

**Описание:** Количество деревьев в Isolation Forest

**Диапазон:** 50 - 500  
**По умолчанию:** 100

**Рекомендации:**
- `50-100`: быстрая детекция, хорошее качество
- `100-200`: баланс скорости и точности
- `200-500`: максимальная точность (медленнее)

**Влияние:**
- Увеличение → более стабильные результаты, но медленнее
- Уменьшение → быстрее, но больше вариативности

##### Классификация типов

**Описание:** Включить/выключить классификацию аномалий по типам

**Тип:** Чекбокс  
**По умолчанию:** [x] Включено

**Влияние:**
- [x] Включено: аномалии классифицируются (spike/dip/drift/noise)
- X Выключено: все аномалии помечаются как "noise"

#### 2. Окно анализа

##### Размер окна (Window Size)

**Описание:** Количество точек для анализа локального контекста

**Диапазон:** 3 - 21  
**По умолчанию:** 11 (±5 точек)

**Рекомендации:**
- `3-5`: для высокочастотных данных
- `7-11`: для типичных данных (5-минутный интервал)
- `15-21`: для низкочастотных данных

**Влияние:**
- Увеличение → более сглаженная классификация
- Уменьшение → более чувствительная к локальным изменениям

##### Порог для Spike/Dip (Spike Threshold)

**Описание:** Минимальное отклонение для классификации как spike/dip

**Диапазон:** 1.0 - 5.0  
**По умолчанию:** 2.0 (2σ)

**Рекомендации:**
- `1.0-1.5`: чувствительная детекция
- `2.0-3.0`: стандартная детекция
- `3.0-5.0`: строгая детекция

**Влияние:**
- Увеличение → меньше ложных срабатываний
- Уменьшение → больше аномалий классифицируется как spike/dip

#### 3. Downsampling

##### Максимальное количество точек (Max Points)

**Описание:** Максимальное количество точек для отображения на графике

**Диапазон:** 500 - 10000  
**По умолчанию:** 3000

**Рекомендации:**
- `500-1000`: для медленных браузеров
- `2000-5000`: оптимальный баланс
- `5000-10000`: для детального анализа (требует больше ресурсов)

**Влияние:**
- Увеличение → более детальный график, но медленнее рендеринг
- Уменьшение → быстрее рендеринг, но меньше деталей

##### Метод downsampling

**Описание:** Алгоритм понижения частоты дискретизации

**Тип:** Выпадающий список  
**Варианты:**
- `min-max`: сохраняет экстремумы (по умолчанию)
- `average`: усредняет значения в bucket'ах
- `first`: берёт первую точку каждого bucket'а

**Рекомендации:**
- `min-max`: для анализа аномалий (рекомендуется)
- `average`: для сглаженных данных
- `first`: для быстрого предпросмотра

#### 4. Корреляции

##### Минимальный порог корреляции (Min Correlation)

**Описание:** Минимальный коэффициент корреляции для отображения

**Диапазон:** 0.0 - 1.0  
**По умолчанию:** 0.3

**Рекомендации:**
- `0.0-0.2`: показывать все корреляции
- `0.3-0.5`: показывать значимые корреляции
- `0.5-1.0`: показывать только сильные корреляции

**Влияние:**
- Увеличение → меньше пар отображается в результатах
- Уменьшение → больше пар отображается

##### Автоматический выбор пар (Auto Select Pairs)

**Описание:** Автоматически выбирать пары с сильной корреляцией для scatter plot

**Тип:** Чекбокс  
**По умолчанию:** [x] Включено

**Влияние:**
- [x] Включено: автоматически строится scatter plot для самой сильной пары
- X Выключено: scatter plot не строится автоматически

## Технические детали

### Производительность

**Время анализа:**
- 1 тег, 7 дней (~10,000 точек): ~2-3 секунды
- 5 тегов, 7 дней (~50,000 точек): ~8-10 секунд
- 1 тег, 90 дней (~130,000 точек): ~15-20 секунд

**Оптимизации:**
- Downsampling уменьшает количество точек для визуализации
- Isolation Forest использует подвыборки (max_samples=256)
- Корреляции вычисляются только для валидных данных

### Ограничения

**Минимальное количество точек:**
- Для Isolation Forest: минимум 10 точек
- Для классификации: минимум 50 точек

**Максимальное количество тегов:**
- Рекомендуется: до 10 тегов
- Технически: без ограничений (но медленно)

**Поддерживаемые типы данных:**
- Числовые значения (FLOAT, INTEGER)
- Timestamps (TIMESTAMP, DATETIME)

### Обработка ошибок

**Типичные ошибки:**

1. **Недостаточно данных**

- Error: Not enough data points (minimum 10 required)

**Решение:** Увеличить период анализа

2. **Отсутствие данных в периоде**

- Error: No data found for the selected period

**Решение:** Проверить наличие данных в БД

3. **Превышение таймаута**

- Error: Analysis timeout after 60 seconds

**Решение:** Уменьшить период или количество тегов

### Логирование

Модуль использует `structlog` для структурированного логирования.

**Уровни логирования:**
- `DEBUG`: детальная информация о каждом шаге
- `INFO`: основные события (начало/конец анализа)
- `WARNING`: проблемы с данными (пропуски, дубликаты)
- `ERROR`: критические ошибки

**Пример лога:**
```
2026-06-26 10:00:00 [info] Starting DDA analysis tags=["TAG1", "TAG2"] period="7d"
2026-06-26 10:00:02 [info] Data fetched points=10080 tag="TAG1"
2026-06-26 10:00:03 [info] Running Isolation Forest contamination=0.08 n_estimators=100
2026-06-26 10:00:05 [info] Anomalies detected total=42 types={"spike": 15, "dip": 12, "drift": 8, "noise": 7}
2026-06-26 10:00:06 [info] Analysis completed duration_ms=6000
```

## Часто задаваемые вопросы (FAQ)

### Q: Почему некоторые аномалии не классифицируются?

**A:** Алгоритм классифицирует аномалии на основе локального контекста. Если аномалия не соответствует критериям spike/dip/drift, она помечается как "noise". Можно настроить порог классификации в конфигураторе.

### Q: Можно ли анализировать более 10 тегов одновременно?

**A:** Технически да, но это будет медленно. Рекомендуется анализировать не более 5-10 тегов за раз. Для больших наборов данных используйте последовательный анализ.

### Q: Почему графики выглядят "сжатыми"?

**A:** Это результат downsampling. Увеличьте параметр "Max Points" в конфигураторе для более детального отображения (но это замедлит рендеринг).

### Q: Как экспортировать результаты?

**A:** Используйте кнопку "Download PNG" в модалке графика (кнопка ⛶ на графике). Также можно сохранить анализ через кнопку "Save" и загрузить его позже.

### Q: Почему корреляция показывает 0?

**A:** Возможные причины:
- Нет перекрывающихся данных между тегами
- Данные слишком зашумлены
- Корреляция действительно отсутствует

Проверьте наличие данных для обоих тегов в выбранном периоде.
